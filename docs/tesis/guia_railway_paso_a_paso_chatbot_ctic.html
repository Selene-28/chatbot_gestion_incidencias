Cómo subir el chatbot a internet con Railway

Guía clic a clic, sin instalar Docker ni Python en tu computadora.

Al terminar tendrás una dirección https://algo.up.railway.app con el chat (/demo.html) y el panel (/panel). Después pegas un botón en la web de la facultad.

Tiempo: 30–60 minutos de clics más 15–25 minutos de espera en la primera construcción. Costo: plan Hobby de Railway (tarjeta). El plan gratis no alcanza: este chatbot necesita memoria. Railway sirve para la tesis y demos; a largo plazo los datos de la comunidad deberían estar en un servidor de la UNAC.

Antes de empezar

  • Plan Hobby de Railway.
  • Rama a desplegar: cursor/demo-api-same-origin-2754 (o master cuando esta guía ya esté unida).
  • Anota en papel las contraseñas que inventes. No las publiques.

Paso 1 — Cuenta

Abre https://railway.com → Login with GitHub → acepta permisos → plan Hobby.

Paso 2 — Proyecto vacío

New Project → Empty project. No elijas “Deploy from GitHub” todavía: Railway pensaría que hay un solo programa. Ponle nombre, por ejemplo chatbot-ctic.

Paso 3 — Contraseñas compartidas

En el proyecto, Variables (Shared / Raw Editor). Abre en GitHub el archivo deploy/railway/variables.compartidas.env, copia, cambia todos los CAMBIAR-… y pega. ANTHROPIC_API_KEY puede quedar en “cambiar”: el chat igual registra tickets y busca en el manual.

Paso 4 — Cuatro cajas (nombres exactos)

Orden

Nombre

Qué es

1

mysql

Base de datos

2

ticket-service

Tickets y panel

3

chatbot-api

Cerebro del chat (2 GB de RAM)

4

nginx

Puerta a internet (la única pública)

Cada caja: + New → GitHub Repo → el mismo repositorio. Luego Settings:

mysql: nombre mysql. Root Directory vacío. Dockerfile path: db/Dockerfile. Volume: /var/lib/mysql. Espera Success.

ticket-service: Root Directory services/ticket-service. Volume /data/uploads. Variable:

DB_URL=mysql+asyncmy://tickets:${{DB_TICKETS_PASSWORD}}@mysql.railway.internal:3306/tickets_db
UPLOADS_DIR=/data/uploads

chatbot-api: Root Directory services/chatbot-api. Volume /data/chroma. RAM mínimo 2 GB. El primer build tarda 15–25 min. Variables:

DB_URL=mysql+asyncmy://chatbot:${{DB_CHATBOT_PASSWORD}}@mysql.railway.internal:3306/chatbot_db
TICKETS_API_BASE_URL=http://ticket-service.railway.internal:8001
CHROMA_DIR=/data/chroma
CARGAR_KB_AL_ARRANCAR=1

nginx: Root Directory vacío. Dockerfile path: deploy/nginx/Dockerfile. Variables:

CHATBOT_UPSTREAM=http://chatbot-api.railway.internal:8000
TICKETS_UPSTREAM=http://ticket-service.railway.internal:8001

En nginx: Settings → Networking → Generate Domain. Copia la URL https://….up.railway.app. En chatbot-api añade PUBLIC_APP_URL=https://TU-URL.up.railway.app (sin barra al final) y deja que vuelva a desplegar.

Paso 6 — Botón en tu página web

<script
src="https://TU-URL/widget/widget.js"
data-api="https://TU-URL/api"
defer>
</script>

En WordPress: plugin Insert Headers and Footers o Code Snippets, pegar en el Footer de todas las páginas. En ALLOWED_ORIGINS de chatbot-api agrega https://fiis.unac.edu.pe y https://www.fiis.unac.edu.pe.

Si algo falla

Repo no aparece: da acceso a Railway en la GitHub App. Build rojo: sube RAM de chatbot-api a 2 GB. 502: nombres de las 4 cajas mal escritos. Chat no conecta: falta PUBLIC_APP_URL con https. Panel no entra: la contraseña SEED solo aplica al primer arranque.

Si te trabas, manda una captura de Railway (sin contraseñas) y te decimos el siguiente clic.
